Собрано 31.10.2026 детерминированными скриптами `tools/analyze_tracks.py` и `tools/analyze_court.py`
(журналы и протоколы — только чтение, П16). Таблицы — `REPORT.md`, `COURT.md`; сырьё — `report.json`, `court.json`.

## Что это значит для продукта (сначала главное)

**За 3,5 месяца и 3567 сверенных исходов ни один трек не показал умения предсказывать.** Везде, где
вероятности сравниваются с простой «базовой частотой» (постоянным прогнозом «сбывается в X% случаев»),
они её не обыгрывают. Система честно считает, запечатывает и сверяет — но то, что она запечатывает,
не содержит информации сверх базовой частоты.

Поправка к вчерашнему выводу («калибровочный трек — единственный, кто работает»): **это было неверно.**
Его Brier 0.216 против «монетки» 0.25 возникает из конструкции (три вложенных порога: «выше −0.5σ» —
сбывается в 73%, «выше +0.5σ» — в 27%), а не из умения. Внутри каждого порога skill = 0 (−0.009 / −0.001 / −0.006).
Это хорошо выставленная гауссова база по реализованной волатильности, не прогноз.

## Гипотезы 15.07 — проверены и НЕ подтвердились

1. **«Ближнее звено с высоким r² попадает чаще».** Нет. По r² (сила связи в истории): < 0.02 → 45%,
   0.10–0.20 → 54%, ≥ 0.40 → 56% при заявленных 59% — разброс в пределах шума, skill во всех корзинах ≤ 0.
   Глубина цепочки: 1 звено → 48%, 2 → 51%, 3 → 36% (n=50). Ярус A (связь подтверждена историей) → 50%,
   ярус C (гипотеза картографа) → 48%. Ближнее звено яруса A (n=193) → 48.7% против глубоких с C (n=708) → 49.6%.
2. **Сырая уверенность движка** (до сжатия П-1): в корзине ≥ 0.55 сбылось 44.8% — уверенность системы
   слегка *анти*-информативна. Сжатие П-1 к базовой частоте было правильным решением (Brier 0.255 → 0.250),
   и на 01.10 крон корректно пере-подогнал p0 до 0.467.
3. **Исследовательский суд A1 (балл силы 0–5)** — 501 вердикт с исходом за 101 прогон. Корреляция балла с
   исходом **0.038** (= нет). Балл < 2 → 43%, 2–2.5 → 51%, 2.5–3 → 47.5%. Полоса «слабая» 48.5%, «средняя» 47.3%.
   Структурная причина: судья ставит `mechanism_real ≤ 2` в 498 из 500 случаев, `asymmetry ≤ 2` в 500 из 500,
   `timing_amplitude ≤ 2` в 495 из 496 — т.е. по трём из шести критериев все идеи одинаково слабы, а балл
   различается только «неочевидностью» и «проверяемостью», которые с исходом не связаны (48% в обеих корзинах).
   **Топ-3 ранжирует шум.** Сегодняшняя подача №1 (NVDA, «сила 2.8/5») в собственном тексте судьи названа
   «статистической догадкой, а не подтверждённым edge».
4. **Денежный суд §11** — 116 вердиктов, **все РАЗБИТА**, 124 дня без денежной печати. Разбитые идеи сбылись
   в 52.6% — ровно как всё остальное. Суд не отличает хорошее от плохого; он просто закрыт.

## «Где сигнал?» — первый систематический проход (tools/find_signal.py → SIGNAL.md)

порядок звена, чокпоинт, лаг узла и ребра, якорь, исток, тикер, месяц, знак, ярусы, глубина, r², амплитуда,
день недели) — 115 срезов с n ≥ 40, биномиальный тест против базы 0.483, поправка Бенджамини–Хохберга q=0.10.
**Прошло FDR: 0.** Лучшие кандидаты (не выжили): «чокпоинт × вверх» 56% (n=327, p=0.006); «авторская карта ×
вниз» 33% (n=73) и «авторская карта, 4-й порядок» 33% (n=54) — т.е. единственная авторская цепочка (ai_power)
на дальних звеньях промахивается чаще монетки; NUE 32% (n=59), JETS 31% (n=51). При 115 тестах ~11 «значимых»
на уровне 0.1 ожидаются случайно — получили 13. Это шум.

## Что из этого следует (рекомендация, не решение)

Дальнейшие этапы дорожной карты (B2 исторические аналоги, Этап 4 движок амплитуды, Этап 5 феномены)
строятся поверх движка, у которого **нигде не измерен сигнал**. Добавлять к нему слои — значит ранжировать
шум точнее. Честный следующий шаг — не «что ещё прикрутить», а «где вообще есть сигнал»:

1. **Перестать показывать владельцу балл силы как ранжир**, пока он не связан с исходами (сейчас это
   декорация с корреляцией 0.04). Подача должна говорить: «за 3,5 месяца идеи этого типа сбывались в 48%».
2. **Искать сигнал там, где он измерим**: например, протестировать на 1932 провизорных исходах, есть ли
   подмножество (по типу события, по сектору, по лагу, по знаку шока истока) с попаданием статистически
   выше базы — это один скрипт, данные уже лежат. Если такого подмножества нет — это и есть ответ.
3. **Источники данных** — чинить сейчас: GDELT (снизить нагрузку, алерт при нулевом дне), Trends (видимость
   429, кэп ключей по тому, что реально влезает в лимит, стоп мусорных ключей из кластеров).
